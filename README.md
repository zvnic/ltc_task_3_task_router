# Task Router — диспетчерская выездных инженеров

Веб-прототип планирует один рабочий день выездных бригад: импортирует заявки,
строит последовательный baseline и два оптимизированных варианта, проверяет каждый
план независимым валидатором, показывает маршруты и позволяет пересчитать остаток
дня после новой заявки.

Приложение рассчитано на локальный запуск: наружу публикуется только web-интерфейс
на `127.0.0.1`, API и PostgreSQL доступны лишь внутри Docker Compose.

## Быстрый локальный запуск

Понадобятся:

- Docker Engine или Docker Desktop;
- Docker Compose v2.20+;
- Bash и GNU Make;
- доступ в интернет при первой сборке образов и для внешней подложки/геометрии карты.

Host Python, Node.js и PostgreSQL не нужны.

```bash
make init
```

Команда создаст `.env`, каталоги `data/inbox` и `artifacts`, сгенерирует пароли БД
и ключ сессий. Перед первым запуском замените в `.env` значение:

```dotenv
APP_PASSWORD=задайте-свой-локальный-пароль
```

Затем выполните полный bootstrap:

```bash
make bootstrap
```

Bootstrap собирает образы, запускает PostgreSQL, применяет Alembic-миграции,
создаёт тестовую БД, загружает демонстрационные наборы, поднимает приложение и
выполняет smoke-проверку.

Откройте [http://localhost:18032](http://localhost:18032) и войдите с паролем из
`APP_PASSWORD`. Порт задаётся переменной `WEB_PORT` в `.env`.

Проверка состояния:

```bash
make ps
make smoke
make logs SERVICE=api
```

Остановить приложение с сохранением данных:

```bash
make down
```

Volume PostgreSQL при `make down` сохраняется. Его удаляет только явная команда
`make clean CONFIRM=delete-data`.

## Основной сценарий

1. Выбрать один из демонстрационных наборов или импортировать CSV.
2. Проверить заявки, инженеров и действующие нормативы.
3. Запустить один метод либо сравнение решателей.
4. Посмотреть выбранный план, причины неназначения, расписание и карту.
5. Добавить обычную или аварийную заявку в течение дня.
6. Сравнить новый immutable-план с предыдущей версией.

Доступные методы:

- `baseline_v1` — входной порядок, первый допустимый инженер, добавление только в
  конец маршрута;
- `ortools_gls_v1` — VRPTW-модель OR-Tools с Guided Local Search;
- `insertion_ls_v1` — конструктивная вставка по приросту расстояния и локальный
  поиск.

Все методы получают один snapshot. Результат публикуется только после независимой
проверки, а лучший кандидат выбирается общей функцией сравнения. Ограниченный
поиск не считается доказательством глобального оптимума.

## Управление проектом

```bash
make help                 # полный список команд
make doctor               # Docker, Compose, .env и исходные файлы
make build                # production и tools-образы
make up                   # запуск готовых образов
make dev                  # hot reload backend/frontend
make restart              # перезапуск сервисов
make lint                 # Ruff + ESLint
make typecheck            # mypy + TypeScript
make test                 # pytest + Vitest
make e2e                  # Playwright
make check                # lint → typecheck → test → e2e → smoke
make benchmark            # измерения и отчёты в artifacts/benchmark
make backup               # PostgreSQL dump в artifacts/backups
```

Импорт и расчёт из CLI выполняются только через контейнеры:

```bash
# Файлы должны находиться в data/inbox; передаётся только basename.
make import FILE=requests.csv
make import-reference FILE=control.csv DATASET_ID=<uuid>
make plan DATASET_ID=<uuid>
make replan PLAN_ID=<uuid> EVENT_FILE=urgent_event.json
```

## Обновление уже запущенного стенда

```bash
git pull --ff-only
make build
make up
make smoke
```

При старте runtime-контейнер API применяет миграции из того же свежего образа и
лишь затем запускает Uvicorn. Readiness дополнительно проверяет, что версия схемы
совпадает с Alembic head приложения.

## Данные и ограничения результата

Оригиналы в `data/source` не изменяются. В исходных CSV отсутствуют координаты, длительности,
характеристики инженеров, навыки и транспорт. Эти поля добавлены из
версионируемых демонстрационных fixtures и помечены в UI/API.

Расчётная матрица решателя использует `haversine_by_transport_v5`: расстояние по
сфере, коэффициент непрямолинейности, среднюю скорость в городе и за МКАД, накладное
время и нижнюю границу времени для каждого транспорта. Общественный транспорт
откалиброван по Яндекс Картам. Поэтому расчётный пробег — оценка, а не
фактический трек. Геометрия выбранного маршрута на карте запрашивается отдельно у
Valhalla, с OSRM-совместимым failover. Для общественного транспорта точная
геометрия доступна через настроенный `OTP_URL`; без него UI использует внешний
справочный слой и не подменяет расчёт прямой линией.

Контрольное распределение применяется только для сопоставления состава заявок.
Оно не является baseline и не содержит данных для расчёта фактического пробега.
Система моделирует диспетчерский сценарий, а не реальный GPS-мониторинг.

## Если запуск не удался

- `make doctor` — проверяет обязательные зависимости и конфигурацию.
- `make logs SERVICE=api` — показывает последние логи API.
- Если порт занят, измените `WEB_PORT` в `.env`, затем выполните `make up`.
- При `schema_pending` или `schema_outdated` выполните `make build && make up`.
- При недоступности внешнего роутера расчёт плана продолжает работать, но точная
  геометрия карты может быть временно недоступна.
- После восстановления БД выполните `make migrate`, `make up`, `make smoke`.

## Доступ (публичный режим по умолчанию)

По умолчанию приложение **открыто без пароля** (`AUTH_ENABLED=false`):

- API и UI доступны без cookie / login
- `/api/v1/auth/status` → `{ "authenticated": true, "auth_enabled": false }`
- кнопка «Выйти» скрыта; `/login` сразу перенаправляет в приложение

Опциональный password-gate (демо / закрытый стенд):

- `AUTH_ENABLED=true`
- `APP_PASSWORD` — общий пароль входа
- `AUTH_SECRET` — секрет подписи session-cookie (длинная случайная строка)
- cookie `beeline_session` — HttpOnly, SameSite=Lax; в `APP_ENV=prod` также Secure
- middleware закрывает `/api/v1/*` кроме `/auth/*` и `/health*`
- frontend при 401 / отсутствии сессии уводит на `/login`

`scripts/init_env.sh` создаёт `.env` с `AUTH_ENABLED=false`. Чтобы включить пароль — выставьте `AUTH_ENABLED=true` и задайте `APP_PASSWORD` / `AUTH_SECRET`.
